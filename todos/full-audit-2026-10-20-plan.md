## 10. Verification discipline and recurring risk classes

- Never merge a claim the tools can settle: run the scanners, read the cited lines, grep all of `src` for producers/consumers.
- Parent in-tree verification beats agent inference; two independent agents get an **(independent)** tag — that is how P1-5, P2-45, P2-48, P2-52 and P2-33 (security-class) entered.
- Tests that assert a mock's own literal are not coverage (P2-72, P2-73, P2-77, P2-112, P2-76): the fix must make the test fail before it passes.
- Recurring classes to re-check on every audit: renderer types checked by no gate; coverage excludes `main.ts`/`ipc-handlers.ts`/`components/**`/`preload/**`; gate asymmetry between read and destructive channels (`fs:listDir` gated vs `fs:listDirs` not, `fs:exists` gated vs `fs:isDirectory` not, `fs:watchDir` gated vs `fs:unwatchDir` not, every fs channel gated vs `pty:create` not, `mcp:addServer` gates `configDir` vs `profiles:provision` not); consent read in `settings-guard` (default dir) vs enforced in the spawn path (profile dir); release jobs racing one tag with no artifact verification; fail-open digest checks and upstream defaults in `bin/vibeyard.js`/`auto-updater.ts`/`team-config.ts`.
