# Provider contracts

Project context menu → Settings always offers a coding provider and a profile scoped to that provider. `ProjectRecord.defaultProvider` is persisted; absent means the global default. New CLI sessions use explicit override → project default → global default → Claude. Plans and unpinned team chats also prefer an explicit project default over the active tab. Changing the provider resets an incompatible project profile. Running PTYs are not restarted by saving these settings. New-session and board dialogs preselect the project provider.

The registry in `src/main/providers/registry.ts` registers Claude Code, Codex CLI, GitHub Copilot, Gemini CLI, Pi and Oh my Pi. Provider capabilities determine which UI and status paths are enabled; do not assume all providers support profiles, hooks, resume, cost or self titles.

`src/main/pty-manager.ts` builds an argv array for node-pty. Never set `shell: true`. On Windows, `quoteArgForCmdExe` wraps each `cmd.exe` token and rejects double quotes that cannot be conveyed safely. `partitionUserEnv` (`src/shared/env-vars.ts:95-109`) splits the user's `KEY=VALUE` env into what may be merged over the provider environment and what must not be: the provider-owned keys — `CLAUDE_CONFIG_DIR`, `PI_CODING_AGENT_DIR`, `PI_CONFIG_DIR`, `PI_PROFILE`, `OMP_PROFILE`, `CLAUDE_IDE_SESSION_ID`, `VIBEYARD_SESSION_ID`, `COPILOT_HOME` (`PROVIDER_OWNED_ENV_KEYS`, `env-vars.ts:72-81`) — are dropped and named on the console, never applied (`src/main/pty-manager.ts:321-327`). The match folds case (`env-vars.ts:102`) because Windows env names are case-insensitive; `PATH` is deliberately NOT in the list, so a user override of it wins (`env-vars.ts:69-70`, `src/main/pty-manager.ts:316-319`, merge at `:328`). Raw extra args are tokenized by the shared `tokenizeArgs` (`src/shared/launch-args.ts:26`): space, tab, CR and LF delimit; single quotes are literal content; double quotes honour `\"` and `\\`; an unquoted backslash escapes only a quote or another backslash, so `C:\Users\me` survives unquoted; an unclosed quote consumes the rest of the input; empty arguments (`""`, `''`) are preserved; and tokenizing never throws (`launch-args.ts:9-21`). All six providers append `tokenizeArgs(opts.extraArgs)` to argv (`claude-provider.ts:118`, `codex-provider.ts:80`, `copilot-provider.ts:81`, `gemini-provider.ts:118`, `pi-provider.ts:104`, `omp-provider.ts:98`) — a per-provider whitespace split shipped a quoted value to the CLI as separate arguments. `resolveLaunchSpec` rejects unsupported options before any side effect (`src/main/pty-manager.ts:293-341`): user env keys that move session storage to a root no watcher scans (`UNSUPPORTED_STORAGE_ENV_KEYS` — `PI_CODING_AGENT_SESSION_DIR`, `CODEX_HOME`; `src/shared/launch-args.ts:151-156`, case-folded match `:159-163`), and the extra-arg flags Vibeyard owns (`--profile`, `--session`, `--session-id`, `--session-dir`, `--no-session`, `--resume`, `--continue`, `-r`, `-c`, detected in both `--flag x` and `--flag=x` forms; `launch-args.ts:110-120`), checked on the tokenized user args only — never on the flags Vibeyard itself adds (`src/main/pty-manager.ts:330-334`). Every hit is reported together in one `LaunchSpecError` (`src/main/pty-manager.ts:336-341`). Launch-argument contracts live in each provider's `buildArgs` and are pinned by its test: Claude passes `--session-id <id>` only in the first-run case (a new session whose CLI session id is already known) and resumes with `-r <id>` (`claude-provider.ts buildArgs`, `claude-provider.test.ts`); Copilot resumes with `--resume=<id>` and carries the queued prompt as `-i <prompt>` — the terminal pane hands the initial prompt to every startup-arg provider, so dropping it on resume silently lost a browser-tab / team / Restart Session prompt delivered to a dormant session (`copilot-provider.ts buildArgs`, `copilot-provider.test.ts`). A rejected `LaunchSpec` does not throw into the IPC caller; it reports through the `pty:exit` channel — see [session lifecycle](session-lifecycle.md).

For profile-aware configuration, follow the same profile resolution chain used by spawning. `provider:getConfig` must receive the selected config directory; Pi reads that directory's `mcp.json`. Do not fall back to a different account's default configuration. `removeProfile` refuses removal while sessions or archives still pin it. The MCP write path is symmetric: `addMcpServer`/`removeMcpServer` take the same config directory, so a profiled project's `claude mcp add`/remove lands in `<configDir>/.claude.json` — never `~/.claude.json`. `removeMcpServer` accepts `filePath` echoed back from the list call, so it writes only to a canonicalized allowlist of known config files (`canonicalPath`, which folds case, separators and junctions); a non-listed target throws `Not a writable MCP config path`. The add side gates the renderer-named dir the same way: `configDir` arrives verbatim in the `mcp:*` IPC args and the write target is derived from it, so `addMcpServer` first runs it through `isManagedMcpConfigDir` — the canonicalized dir must equal, or sit inside, a stored profile's `configDir` or a known project path — and a dir the store never handed out throws `Not a writable MCP config path` naming the derived `<configDir>/.claude.json` before anything is written; `mcp:addServer` surfaces a rejection as `{success:false,error}` (`claude-cli.ts addMcpServer`/`isManagedMcpConfigDir`, `claude-cli.test.ts`).

Transcript lookup must match the requested working directory. A matching CLI session ID in another project is insufficient. The session id a Pi/OMP transcript header declares is untrusted input: `sessionHeaderFromWindow` (`src/main/providers/pi-compatible-transcripts.ts:376`, gate at `:381`) accepts it only inside `COMPATIBLE_SESSION_ID_RE` = `/^[A-Za-z0-9_-]{1,128}$/` (`:373`) — the accepted value becomes the session's `cliSessionId`, later an argv token on the Windows `cmd.exe` spawn path and a filename suffix built from it, so the charset excludes every character that could break out of a token, while staying wider than a UUIDv7 so a future id format does not break resume; a header declaring any other id yields no descriptor, so that transcript is neither adopted nor offered as resumable (see [security boundaries](security-boundaries.md)). Pi/OMP exit reasons come from the same bounded reads: `readSessionExitReasonSync` (`pi-compatible-transcripts.ts:326-338`) pulls the last 16 KiB (`TAIL_READ_BYTES`, `:70`) and retries once at the 4 MiB cap (`MAX_STATUS_TAIL_BYTES`, `:87`) when that window holds no complete line, and `sessionExitReasonFromTail` (`:281-319`) walks backwards across crash-flush appends only (`tool_execution_start` / `toolResult`, bounded by `MAX_FLUSH_LINES = 32`, `:285`) — any real user/assistant entry ends the scan, so a marker the CLI resumed past is history, not this launch's exit. Claude, Codex, Copilot and Gemini report status through hooks where supported; Pi and Oh my Pi poll transcripts. See [session lifecycle](session-lifecycle.md) and [hook compatibility](../HOOKS.md).

Codex rollouts live under `~/.codex/sessions/YYYY/MM/DD/rollout-<ts>-<id>.jsonl`; recent Codex builds write zstd-compressed `.jsonl.zst` instead. Indexing and transcript resolution accept both forms — discovery matches `rollout-…-<id>.jsonl` and `.jsonl.zst`, and indexing decompresses a bounded prefix of the compressed file (`32af0b4`). When hooks do not report the CLI session ID, the fallback watcher attributes new rollout files to the tab that launched Codex: registration carries the launch cwd and a rollout is assigned only to a tab registered for the cwd in its `session_meta` line, so an external `codex` run (terminal, CI) no longer hands its transcript to the oldest pending tab. Within one cwd the oldest pending tab pairs with the oldest rollout, and a failed CLI-id write leaves the tab pending with the id unclaimed so the next scan retries; scan-cost pruning and cache bounds are in [session lifecycle](session-lifecycle.md). `codex-provider.cleanup()` calls `stopCodexSessionWatcher()`, so the rollout watcher (a recursive `fs.watch` plus a 2 s poll) is stopped on provider cleanup / quit. Windows status hook commands pin the probed interpreter (`python`, else the `py -3` launcher; see `src/main/prerequisites.ts`) in every generator including `statusCmd`; bare `python` is the App Execution alias on many machines and silently kills every `event:status` hook there (`e866e4a`).

Global search discovery accepts an optional abort signal and stops scheduling work when cancelled. Search indexing shares a four-operation budget and in-flight reads across requests. Workers retain compact results, not the full corpus. A versioned local derived index (`search-index-v2` under Electron user data) reuses unchanged source text after memory-cache eviction; mtime, size and ctime invalidate a record. Deletion pruning runs only after a complete, uncancelled discovery pass: `discoverTranscripts` returns a `TranscriptDiscovery` `{ descriptors, complete, incompleteRoots }` (`src/main/providers/provider.ts:25-29`, contract comment `:54-62`), and a scan root that cannot be listed for any reason other than absence reports incomplete — `ENOENT`/`ENOTDIR` mean missing (`isMissingRootError`, `src/main/providers/transcript-utils.ts:119-122`), every other failure propagates from `readdirForDiscovery` (`:131-142`) and records the root via `TranscriptDiscoveryScan.collect` (`:153-159`). For Claude, Pi and OMP a mid-scan failure drops that root's partial descriptors too: each root's scan returns its list and the list is appended to the corpus only on success (e.g. `claude-provider.ts:186-188`, `pi-provider.ts:250-251`); Copilot's only scan failure is the leading root readdir, which precedes every descriptor (`copilot-provider.ts:148-149`); Codex's tree walk and Gemini's project walk accumulate inline, so their pre-failure descriptors stay in the partial list (`codex-provider.ts:219`, `gemini-provider.ts:271`) — immaterial for deletion, because `pruneSearchIndex` is never fed an incomplete scan: it runs only under `if (!signal?.aborted && discovery.complete)` (`src/main/session-deep-search.ts:242-244`), so derived index entries for an incomplete root's sources are never unlinked (`src/main/session-search-index.ts:62-69`), and each incomplete root is warned once per pass (`src/main/session-deep-search.ts:239-241`). This index contains extracted user text and may be deleted to rebuild it; bump its version when extraction semantics change. Its disk size scales with history, while each text record is capped at 50 Ki characters including join separators and the in-memory text cache has an aggregate budget.

See [performance and resource limits](performance.md) for the exact cache budgets, plaintext disk-index lifecycle, cancellation boundaries, and remaining discovery costs. The four-operation indexing budget is not a global limit for all discovery filesystem work.
