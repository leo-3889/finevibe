# Security boundaries

The renderer sends privileged work through preload and main-process IPC. Validate project paths, including symlinks, before filesystem access. `statusFilePath()` validates UI session IDs before using them as filenames in the hook-status directory under `os.tmpdir()/vibeyard`. A pasted clipboard image crosses the same boundary as bytes only: main generates the filename inside `os.tmpdir()/vibeyard-paste` and allowlists the image formats, so the renderer cannot aim a paste at a path. Clipboard file lists (browser `FileNameW`, `CF_HDROP`, the Finder plist, `text/uri-list`) are read by main and injected as path text only — never written to, and relative names are dropped — so a paste can name files but can never choose a write target.

PTY arguments and environment variables cross a trust boundary. Keep `shell: false`, Windows argument quoting/rejection, and provider-owned environment filtering described in [provider contracts](provider-contracts.md). The embedded webview and Chrome-cookie import handle third-party content and account data; keep browser partitions and permission checks separate from terminal state.

The main window runs with `nodeIntegration: false`, `contextIsolation: true` and `sandbox: true`; the preload reaches main only through `contextBridge` and sandbox-safe Electron modules, so it cannot import local CommonJS helpers (the zoom bounds are duplicated in `src/preload/preload.ts` for that reason). A `<webview>` guest's privileges are renderer-controlled, so `will-attach-webview` on the main window's host webContents (Electron 41 has no App-level event) pins `nodeIntegration` off, `contextIsolation`/`sandbox` on, and keeps a `preload` only when it is the shipped `browser-tab-preload.js`; destinations stay unrestricted because loading arbitrary remote pages is the feature. Guest window opens are denied and http(s) targets go to the OS browser through the validated `app:openExternal` path, so a popup can never inherit a tab's session partition or imported Cookie jar. The URL bar rejects `javascript:` and `view-source:`.

P2P sharing is opt-in. The host chooses read-only or read-write access; read-write gives the peer terminal command execution. A generated 128-bit share key encrypts connection codes and authenticates the data channel. Do not send scrollback, live output or resize frames before host verification. Treat both the key and codes as sensitive and end a share when the user closes it.

Global search writes derived plaintext user text and working directories to `search-index-v2` under Electron user data. Source-path hashes obscure filenames but are not encryption. The index is rebuildable and separate from provider transcripts and the persisted application state. See [performance and resource limits](performance.md) for retention, invalidation and rebuild instructions.
