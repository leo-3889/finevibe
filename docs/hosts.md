# Hosts (multi-host SSH)

FineVibe enrolls remote SSH hosts (Settings → Hosts), runs interactive shells on them, and — since Phase 2 (`todos/archives/per-host-providers-plan.md`, local-only) — runs coding-tool sessions, provider file reads, settings sync, and the Add-project verbs on them. Host-keyed provider behavior is in [provider contracts](provider-contracts.md); remote session status/transcripts in [session lifecycle](session-lifecycle.md).

## Registry

`HostRecord` (`src/shared/types.ts`) lives in `PersistedState.hosts` (`src/main/store.ts`). Every load path (`loadState`, `saveState`, `saveStateSync`, `defaultState`) normalizes the array through `validateHostRecordShape` (`src/shared/ssh-host.ts`): entries that are not objects, miss required fields, carry an out-of-range port, or hold a non-POSIX `defaultFolder` are dropped, never repaired. The renderer hydrates the same shape (`hydrateLoadedState`, `src/renderer/state/persistence.ts`) but never writes hosts directly — all mutations go through `hosts:*` IPC into `src/main/hosts/host-registry.ts` (create/update/delete; create honors a draft `id` so a pre-generated keypair directory matches its host).

Fields that matter: `authKind` (`key` | `password`), `managedKey` (FineVibe-generated pair under `<userData>/hosts/<id>/`), `hostFingerprint` (pinned SHA256 — enrollment requires a pin), `prerequisites` (last probe of remote coding-tool binaries), `defaultFolder` (POSIX path, the remote cwd for shells; default `~/.finevibe`), `enrollmentStatus` (`draft` → `probing` → `auth-ok` → `enrolled` | `partial` | `failed`).

## Enrollment lifecycle

`src/main/hosts/enrollment.ts`:

- `testHost` — connect + auth probe. First contact yields `newFingerprint`; the UI must show it and get explicit approval (`hosts:approveHostKey`) before anything is pinned. A pinned key that differs is `hostKeyChanged` — every later connect refuses (hard fail, no TOFU-retry).
- `enrollHost` — requires a pinned fingerprint. Steps: connect → env → key-deploy (managed key: append public key to remote `authorized_keys` via a marker block, idempotent) → prereqs (binary probe) → dirs (`mkdir -p defaultFolder`). A non-POSIX remote shell fails the record (R2: enrollment target is POSIX). Missing binaries land as `partial` with the per-binary report kept in `prerequisites`.
- `unenrollHost` — rewrites the remote `authorized_keys` removing only FineVibe's marker block, then deletes the managed keypair and keychain entries. Deletion of a host (`hosts:delete`) runs unenroll first for enrolled records (UI-ordered).
- Host hook merge (per-host providers T2) — enrollment merges FineVibe's status-writer hooks into each probed tool's `settings.json` (marker-scoped: every handler command carries `# finevibe-hook`, so merge is idempotent and unenroll strips exactly the block). Foreign keys/hooks survive *content*-identical; when the block changes, the whole file is re-serialized (2-space JSON + trailing newline), so duplicate keys collapse and escapes normalize — byte-identical only on the no-op paths. The `.bak` rule (T3) is the recovery story for a bad rewrite.
- Settings sync (per-host providers T3, UR-5) — push-only local → host for pi/pi-bolt/omp. The bundle builder (`src/main/hosts/settings-bundle.ts`) IS the allowlist: the §4 file-set table per provider (pi: `~/.pi/agent` settings/AGENTS/mcp/skills; pi-bolt adds the npm manifests; omp: agent settings/keybindings + plugin manifests), deduped by path (pi/pi-bolt share the tree), settings.json pushed hook-stripped, every file LF-normalized; `sessions`/`cache`/`node_modules`/`ssh-remote-config.json` never enter a walk. The push (`src/main/hosts/settings-sync.ts`) writes via the provider-fs seam with the one-`.bak`-per-path rule (replaced each sync), `mkdir -p` on the exec lane, records sha256 per pushed file in `HostRecord.settingsSync` (`{providers, lastSyncAt, lastSyncHashes}`), and runs `npm install` on the host for the manifest trees (skipped with a warning when the prereq probe found no node). Drift (remote hash ≠ stored hash) blocks the push until the UI confirms Overwrite (`hosts:syncSettings` with `confirmOverwrite`).
- Remote open/add folder (per-host providers T5, UR-6) — the Add-project modal's verbs on a host live in `src/main/hosts/remote-fs.ts`: `listRemoteDirs` (sftp readdir, dirs-only, 500-entry cap, `fs:listDirs` shape), `statRemotePath`, `ensureRemoteDir` (`mkdir -p` + `printf` echo answering main's canonical absolute path — the same "persist what main answers" rule as local `fs:ensureDirectory`), `cloneRemoteRepo` (the local `detectGitCheckoutUrl` gate verbatim, exists-and-not-empty destination pre-check over sftp, `git clone --` with both words shell-quoted, the local 10-min clone timeout). The file-tree rails (`listRemoteDir` files+dirs 2000-entry cap, `readRemoteFile` size-capped + NUL head-sniff) carry one more gate — `isRemotePathInKnownProject`: the path must sit under a persisted project root of the same host; the dir-browser verbs above stay on the looser T5 gate (the HostRecord is their consent). Path safety is one function: `normalizeRemotePath` accepts only `~`, `~/…` and `/…`, rejects `..` on the RAW segments (a normalized `~/../etc` would silently re-anchor), relatives, bare `~user`, NUL; the renderer never canonicalizes remote paths against the local disk. The gate is host-exists + `enrolled|partial` (`gateHost`, the settings-sync shape) — deliberately NO enumerate-confirm dialog: the local `fs:listDirs` confirm (P1-19) guards a local privacy concept, and on a registry host the consent IS the enrolled `HostRecord` (council R-1, see [security boundaries](security-boundaries.md)).

Status transitions push `hosts:status` events to all windows; the section re-renders from `hosts:list`.

## Secrets

`src/main/hosts/secrets.ts` wraps Electron `safeStorage`. Host passwords are stored under keychain key `<hostId>`, key passphrases under `keypass:<hostId>`. The IPC surface is write-only (`hosts:setSecret`, `hosts:forgetPassword`): no channel ever reads a secret back to the renderer; ssh-client pulls secrets in main only. `hosts:secretsAvailable` false (Linux without Secret Service) → the UI shows the R1 banner and key-auth-only guidance; enrollment with `password` auth degrades to prompting per session is NOT implemented — password auth without storage is refused.

## SSH transport

`src/main/hosts/ssh-client.ts` (ssh2). Connections are cached per host id in a FIFO-capped `Map` (`MAX_CACHED_CONNECTIONS`, allowlisted in `src/main/module-map-governance.test.ts`); `forceNew` evicts the exact entry. `hostVerifier` compares the server key against the pinned fingerprint and refuses on mismatch. Shell/PTY traffic for enrolled hosts goes through `spawnShellPty` (`src/main/pty-manager.ts`) spawning the local `ssh -tt -p <port> user@host` binary — the xterm pane and pty:data/pty:exit contract are unchanged; the renderer opens such a tab with `openRemoteShellTab` (`src/renderer/components/project-terminal.ts`), which Phase 1 scopes to the active project's terminal panel.

## Limits

Host name ≤ 64 chars; port 1-65535 (default 22); one password + one keypass per host; connection cache `MAX_CACHED_CONNECTIONS` (exported from `ssh-client.ts`). `defaultFolder` must be a POSIX path (a Windows target path is dropped at validation; Windows targets are R2).

## IPC surface

`hosts:list` `create` `update` `delete` `openShell` `secretsAvailable` `generateKey` `setSecret` `forgetPassword` `test` `approveHostKey` `enroll` `unenroll` `tools` `syncSettings` `syncStatus` `listDirs` `stat` `ensureDir` `cloneRepo`, plus the pushed `hosts:status`. Secrets cross only into main. `hosts:openShell` requires an enrolled record and a fresh `sessionId` owned by the renderer shell pane. `hosts:syncSettings(hostId, providerIds, confirmOverwrite?)` takes ids only — the file set, the local reads, and every remote write are main-side (T3); `hosts:syncStatus(hostId)` reports last-sync metadata + the drift list. The T5 lanes (`listDirs`/`stat`/`ensureDir`/`cloneRepo`) take a host id + strings only; `remote-fs.ts` owns normalization, the gate, argv and quoting. The file-tree rails (`fs:listDir`/`readFile`/`stat`/`exists`/`isDirectory`) take a trailing optional `hostId` (parent plan §11): set to a registry host, each routes over sftp through `remote-fs.ts` — gate `enrolled|partial` + path safety + `isRemotePathInKnownProject` (the path must sit under a persisted project root of the same host, the remote twin of the local read gate); absent/`local` rides the unchanged local rails. No remote watcher: a remote tree refreshes on expand and panel re-render, a remote preview reloads on reopen.
