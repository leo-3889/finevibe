# Session lifecycle

Terminal keyboard input tracks the CLI's DEC private mode 9001 requests. While Win32 input mode is enabled, cursor/navigation keys are sent as Windows key records, preserving modifiers; this avoids ConPTY turning OMP arrow sequences into literal prompt characters. When disabled, xterm handles the keys normally. `win32-terminal-keys.ts` owns this adapter. Select-only settings dialogs take keyboard focus from the terminal when opened.

Hook inspector event ingestion is incremental: each turn reads at most 64 KiB, preserves partial JSONL records and UTF-8 bytes, and schedules further backlog reads. Individual records over 64 KiB are skipped. Renderer retention is bounded by both 2,000 events and 2 Mi characters per session. Closing a session cancels pending ingestion continuations and releases its reader state.

Pi/OMP launches use exclusive session directories — `%APPDATA%\vibeyard\omp-sessions\<uiSessionId>` (Pi: `pi-sessions`), created by `src/main/launch-session-dir.ts` and passed as `--session-dir`. Transcripts therefore never enter the CLI default store (`~/.omp/agent/sessions`), so sessions launched in Vibeyard are invisible to the CLI's default-store resume picker; resume inside the tab's history or pass the launch dir. Provider search scans the per-launch dirs under userData. Discovery shares registration generations per watched directory rather than duplicating complete filename snapshots for each session. Registration still forces a fresh synchronous listing. During polling, directory listings are reused while mtimes are unchanged; rename events invalidate them, and a 30-second reconciliation refreshes them even after missed notifications. Two-second polling still checks for changes. Existing-file exclusion remains in force. Closed tabs keep their dirs; nothing prunes them.

Codex CLI has no hook that reliably reports its session ID. The fallback watcher attributes new rollout files (`~/.codex/sessions/YYYY/MM/DD/rollout-<ts>-<id>.jsonl[.zst]`) to the tabs that launched Codex, keyed by cwd: `registerPendingCodexSession` records the launch cwd, and a rollout is assigned only to a tab registered for the cwd carried in the rollout's `session_meta` line (per-cwd FIFO). Attribution used to be a global FIFO over the shared `~/.codex/history.jsonl`, so any external `codex` run (terminal, CI) hijacked the oldest pending tab with a foreign transcript and a wrong resume target.

The renderer owns session records in `src/renderer/state.ts`; the main process owns PTYs. A non-shell CLI PTY exit destroys and removes its live session. `src/main/ipc-handlers.ts` owns replacement cleanup. A `killPty` that arrives while `spawnPty` is still awaiting records a pending kill that the spawn consumes immediately after registering the PTY, so the CLI tears itself down instead of orphaning; every spawn path that returns without spawning clears the marker so a stale kill cannot hit a later re-spawn of the same id. The UI distinguishes active sessions, archived resumable sessions and history entries. State is saved to `~/.vibeyard/state.json` through an atomic temporary-file rename (main fsyncs on rename) and flushed on quit. Renderer persist is a leading-edge throttle: the first mutation writes immediately, mutations in the following 200 ms coalesce into one trailing save, and `beforeunload` flushes an armed save (`ffcd283`).

Session history tracks CLI sessions from creation: `commitNewSession` records an `active` row (keyed by the live session id) as soon as a CLI tab spawns, so the history panel reflects opens immediately, including sessions that are closed without a prompt. The discovered `cliSessionId` mirrors onto that row; closing finalizes it in place (name, cost, `closedAt`, exit info, `transcriptAvailable`). A `/clear` archive appends a separate closed row for the cleared conversation and never touches the live row. Active rows are exempt from the 500-entry cap, survive Clear History (with bookmarks), and clicking one activates its tab — a live session is never "resumed", which would duplicate it on the same CLI transcript. Renaming a live tab renames its own row; closed rows are immutable history. On state load, rows whose tab did not survive are finalized (closed at load time).

History export lives in `src/main/session-export.ts` and the history context menu. `Export session (zip)` writes `meta.json` (the history entry plus resume coordinates), the provider-native transcript verbatim under `transcript/` when it resolves, readable hook sidecars from `STATUS_DIR` under `sidecars/` when present, and a README. `Export transcript (single file)` copies the transcript verbatim (falling back to `meta.json` when absent). Transcript resolution goes through `provider.getTranscriptPath(cliSessionId, projectPath, configDir, sessionDir)`, passing the exclusive Pi/OMP launch directory whenever the row carries a live session id; transcript-existence checks use the same rule. Imports are not wired — exports are reference snapshots.

Session activity changes on provider hook or transcript events. A completed event moves a linked Kanban task to Done. Closing or losing an unfinished session only clears its live `sessionId`; it does not complete the task. A cancelled Pi/OMP turn (`stopReason: "aborted"`) reports `waiting`, never `completed`, mirroring Claude's `StopFailure`, so interrupting a turn does not mark its Kanban task Done. `board-session-sync.ts` resolves the owning project even while another project is selected.

An abnormal CLI exit is annotated: Pi/OMP can supply a fatal or signal reason through a trailing `session_exit` entry even when the process exits with code 0. The lookup checks the provider's transcript path if the watcher has not resolved one yet and ignores an exit marker older than the current launch. Otherwise the process exit code or signal supplies the reason. Crash history retains PID, code and signal, and offers Resume when a transcript exists. A user-initiated close removes the session before its PTY exit arrives, so it is not reported as a crash.

Numbered default names come from `src/renderer/state/session-naming.ts`. Live provider titles are adopted by `src/renderer/session-title.ts` when automatic titles are enabled and the user has not renamed the session. There is no main-process one-shot naming service or fifth-prompt title pass. A transcript-polled title (Pi/OMP) is only mirrored while a live PTY drives `session-transcript-sync`; a title generated or changed while Vibeyard was closed would otherwise be lost on re-open, so after state load the renderer sends every restored self-titling session to `session:syncRestored`, which re-registers title-only transcript sync (never status, to avoid reviving a stale status on a dead tab) and mirrors the title only for a session whose `cliSessionId` is already known. A session whose id was never persisted stays unresolved — ownership is not inferred from cwd + creation time, which can assign an unrelated conversation and persist it. A resumed session re-registers without the title-only flag and resumes full title/status mirroring; a restored tab closed without a resume releases its title-only entry via `session:release`.

`src/main/file-watcher.ts` watches file-tree and reader directories lazily, including the parent directory to survive atomic replacement. `src/main/git-watcher.ts` watches Git state separately, using recursive watching on Windows/macOS and capped per-directory watching on Linux. Hook `.events` reading advances its byte offset by bytes actually read, retains incomplete line bytes separately, and emits only complete parsed records. A size smaller than the offset resets the reader. The hook-status `fs.watch` carries an `'error'` handler that closes the watcher and schedules one restart five seconds later, so `EMFILE` or a volume unmount cannot crash the main process and take every PTY with it. See [performance and resource limits](performance.md) for exact bounds and oversized-record handling.
